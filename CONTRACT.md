# Contract

Working name: **Arena**. A site with 24/7 live channels where AI plays AI and viewers bet play
money on the outcome. This file fixes the seams between the parts so they can be built in parallel.
It is not a spec: anything not written here is the owner's call.

## Folders and rules

| Folder | What | 
|---|---|
| `program/` | Solana program (Anchor, devnet) and its TypeScript SDK in `program/sdk/` |
| `runner/` | Match runner: the server that runs every channel's show loop |
| `web/` | The site viewers use (built after the design pass) |
| `games/<id>/` | One folder per game (added later) |

## Concepts

`Channel` (a game) → `Match` (one show) → `Window` (one betting question).
One Window = one onchain `Market`: a pooled (parimutuel) bet with 2 to 16 outcomes. Winners split
the whole pool in proportion to their stake. No house fee for now.

Two kinds of window:
- **seeded**: the outcome comes from a deterministic simulation. Nobody may be able to know the seed while betting is open.
- **live**: the outcome comes from model decisions that have not happened yet (LLM matches). No seed.

## 1. Program (owner: `program/`)

Token: one SPL mint, `PLAY`, 6 decimals, mint authority = admin. The UI shows 1 PLAY as $1.

Accounts
- `Config { admin, mint, vault }`: `vault` is a program-owned token account that holds every pool.
- `Market { id: u64, channel: [u8;16], outcome_count: u8, pools: [u64;16], state, close_slot: u64, settle_deadline_slot: u64, commitment: [u8;32], entropy: [u8;32], secret: [u8;32], sim_hash: [u8;32], winner: u8 }`, `state` = `Open | Locked | Settled | Void`.
- `Position { market, owner, amounts: [u64;16], claimed: bool }`, PDA `["pos", market, owner]`.

Instructions
- `initialize` (admin).
- `create_market` (admin): `id, channel, outcome_count, close_slot, settle_deadline_slot, commitment, sim_hash`. `commitment` = `sha256(secret)` for seeded windows, all zeros for live ones.
- `place_bet(outcome, amount)`: signed by the bettor; **the fee payer may be a different account**. Fails at or after `close_slot`. Moves PLAY from the bettor to the vault.
- `lock` (anyone, once `close_slot` has passed): stores `entropy` = the hash of the first slot at or after `close_slot` found in the SlotHashes sysvar, so nobody chooses it. State → `Locked`.
- `settle(secret, winner)` (admin): when `commitment` is non-zero, requires `sha256(secret) == commitment`. Stores both. State → `Settled`.
- `void`: admin any time before settle; anyone after `settle_deadline_slot`. State → `Void`.
- `claim` (anyone, on behalf of a given owner; always pays that owner): `Settled` → `amounts[winner] * total_pool / pools[winner]`; `Void`, or nobody backed the winner → full refund. Once per position.

Seed for seeded windows, computable by anyone after the reveal:
`seed = sha256(secret ‖ entropy ‖ market_pubkey)`.

SDK: `program/sdk`, package name `@arena/sdk`, TypeScript, works in node and the browser.
```ts
createClient({ connection, programId }) => {
  marketPda(id), positionPda(market, owner),
  createMarketIx(...), placeBetIx({ market, owner, outcome, amount }), lockIx(market),
  settleIx(market, { secret, winner }), voidIx(market), claimIx(market, owner),
  fetchMarket(market), fetchPosition(market, owner), fetchPositions(market), fetchPlayBalance(owner),
  computeSeed(secret, entropy, market),            // hex string
}
```
Deliverable besides code: `program/DEPLOYED.json` = `{ cluster, programId, mint, config }`.

## 2. Runner (owner: `runner/`)

Node + TypeScript. HTTP and WebSocket on port **8787**.

### Chain adapter
Everything onchain goes through one interface with two implementations: `MemoryChain`
(`CHAIN=memory`, the default, no network) and `SolanaChain` (`CHAIN=solana`, built on `@arena/sdk`).
```ts
interface ChainAdapter {
  createMarket(a: { id: bigint; channel: string; outcomeCount: number; closeInMs: number; commitment?: Uint8Array; simHash?: Uint8Array }): Promise<{ market: string; closesAt: number }>;
  lock(market: string): Promise<{ entropy: Uint8Array }>;
  settle(market: string, a: { secret?: Uint8Array; winner: number }): Promise<void>;
  void(market: string): Promise<void>;
  claimAll(market: string): Promise<{ owner: string; amount: number }[]>;   // pays every position
  grant(owner: string, amount: number): Promise<void>;                      // faucet
  relay(txBase64: string): Promise<string>;   // adds the fee-payer signature and submits; refuses any tx that touches anything but our program
  getMarket(market: string): Promise<{ pools: number[]; state: string }>;
  getBalance(owner: string): Promise<number>;
}
```

### Channel plugin: how any game plugs in
A channel is a function that runs one match as a script. The runner calls it in a loop forever.
```ts
interface ChannelDef { id: string; title: string; run(show: Show): Promise<void> }

interface Show {
  announce(match: { matchId: string; title: string; entrants: Entrant[]; meta?: unknown }): void;  // lobby starts
  openWindow(w: { question: string; outcomes: { id: string; label: string; entrantId?: string }[]; durationMs: number; seeded: boolean; simHash?: string }): Promise<Win>;
  lock(win: Win): Promise<{ seed?: string }>;   // waits for the close, locks; seeded → returns the seed and publishes it to viewers
  emit(event: GameEvent): void;                 // forwarded to viewers in order
  settle(win: Win, winnerOutcomeId: string): Promise<void>;   // reveals the secret, settles, pays everyone out
  voidWindow(win: Win): Promise<void>;
  sleep(ms: number): Promise<void>;
  end(result: unknown): void;
}
interface Entrant { id: string; name: string; color?: string; avatar?: string; stats?: Record<string, number>; record?: { played: number; wins: number } }
interface GameEvent { type: string; at: number; data?: unknown }   // at = ms since match start
```
A match may open several windows (before the start, between rounds, between attempts).
The runner ships one built-in demo channel, `coinflip` (two entrants, a 20 s seeded random-walk race), so the whole loop runs before any real game is plugged in.

### Feed: WebSocket `/ws?channel=<id>`
JSON messages, each with `type` and `t` (server ms).
```
snapshot       { channel, phase: 'lobby'|'live'|'result'|'intermission', match, windows, recentEvents, serverNow }   // on connect
match          { matchId, title, entrants, meta }
window_open    { windowId, market, question, outcomes, closesAt, seeded }
pools          { windowId, pools: number[], total }            // after every bet
window_locked  { windowId, seed?, entropy?, simHash? }
event          GameEvent
window_settled { windowId, winnerOutcomeId, secret?, payouts: { owner, amount }[] }
window_void    { windowId }
match_end      { result }
chat           { from, text, bot?: boolean }                   // clients send { type: 'chat', name, text }
```

### HTTP
- `GET /channels`, `GET /channels/:id` (same shape as `snapshot`)
- `POST /faucet { owner }` → grants 1000 PLAY, once per key
- `POST /relay { tx }` → signature
- `GET /me/:owner` → `{ balance, positions }`
- `POST /dev/bet { owner, windowId, outcomeId, amount }` (memory chain only)

## 3. Web (owner: `web/`)

Vite + React + TypeScript, dev port **5190**.
- **Silent wallet**: an ed25519 keypair made on first visit and kept in `localStorage`. No sign-in, no extension, no signing prompt. First visit calls `/faucet`. Balance is shown in dollars.
- **Betting**: build the `place_bet` transaction with `@arena/sdk`, sign with the silent key, `POST /relay`.
- **Pages**: home (grid of live channels) and channel (stage where the game mounts, bet panel, chat).

## 4. Games (owner: `games/<id>/`)

Each game ships an ES module the channel page loads:
```ts
export function mount(el: HTMLElement, opts: { assetsBase: string }): GameHandle
interface GameHandle {
  onFeed(msg: unknown): void;                    // every feed message for the channel, in order
  cameras?: string[]; setCamera?(mode: string, entrantId?: string): void;
  highlight?(entrantId: string | null): void;    // the viewer's pick
  destroy(): void;
}
```
Seeded games also export a pure simulation that runs identically in node and the browser:
```ts
simulate(a: { seed: string; entrants: Entrant[]; options?: unknown }): { durationMs: number; events: GameEvent[]; result: unknown }
export const SIM_HASH: string   // sha256 of the simulation bundle; recorded in the market so a replay can name the exact version
```
The game draws the world. The platform owns names, odds, bets, chat and results.

## Addendum (2026-11-18): what the built parts actually do

The program and the runner now exist. Where this file and the code differ, the code and
`runner/README.md` win. The differences that matter to the website and to games:

- **Amounts are integers in PLAY base units** everywhere (1 PLAY = 1,000,000). Divide by 1e6 to show dollars. `GET /config` returns `decimals`.
- **`event` messages nest the game event**: `{ type: 'event', t, event: { type, at, data } }`.
- Extra feed messages: `phase { phase }` on every phase change; `error { message }` to one socket.
- Extra fields: `match.startedAt`; `window_open.simHash` and `.commitment`; `window_locked.pools/total`; `window_void.refunds`; `bot: true` on house-bot payouts. The snapshot adds `title`, `recentChat`, `bots`, and per-window `state / pools / total / payouts`.
- Extra routes: `GET /config` (chain, decimals, programId, mint, feePayer) and `GET /health`.
- `Show` adds `elapsed()` and `signal`; `ChannelDef` adds `intermissionMs`.
- **`/relay` exists only in Solana mode.** In memory mode the website bets through `POST /dev/bet`.
- SDK: admin instructions need the admin key as signer; `placeBetIx` takes an optional `payer` (set it to the runner's `feePayer` from `/config`); `checkRelayTx` allows only `place_bet`, `lock` and `claim`. SDK amounts are `bigint`.
- `runner/src/channels/coinflip.ts` is the reference example for plugging in a game.
- **Sealed windows** (added 2026-11-18, evening): `show.openWindow({ ..., seeded: false, sealed: true })` commits a secret onchain at open and returns a private `win.sealed` (hex, 64 chars) for hidden roles or cards. Nothing about it is broadcast until settle reveals the secret. Anyone can then check `sealed = sha256("arena-sealed" ‖ secret)`. No public seed is derived at lock.
- Tonight's game runs follow `games/COMMON.md` and their own `games/<id>/BRIEF.md`.

## Platform rules (decided 2026-11-18)

- **Viewers never affect a match.** They watch, chat and bet. No votes, power-ups or anything else that reaches the game.
- **Layout of a channel page:** the stream is the page. Chat is a single column on the right, and the prediction lives inside that column, pinned above the messages. No separate betting panel. Very little text around the stream.
- **No sign-in.** Opening the site creates the silent wallet and grants the starting balance.
- Any bot that chats or bets is labelled as a bot.
- Model channels accept any OpenRouter model id; nothing is hard-wired to two named models.

**Sound hooks on GameHandle** (added 2026-11-19, afternoon; see `web/src/games/types.ts`): the site owns
the stream's sound control, like a player on Twitch or Kick.
- `setVolume(v)`: master volume 0 to 1 for everything the game plays (0 = muted). Called at mount and
  on every change. A game draws no sound button of its own.
- `unlockAudio()`: the viewer has clicked or pressed a key somewhere on the page, so the browser now
  allows sound. Create or resume the AudioContext and start. Called at mount when that has already
  happened (they clicked a channel on the home page), otherwise on their first click anywhere. A game
  never waits for a click on its own stage and never shows a "click for sound" hint.
- Until a game has `unlockAudio`, the site sends its stage one synthetic `pointerdown` instead.
